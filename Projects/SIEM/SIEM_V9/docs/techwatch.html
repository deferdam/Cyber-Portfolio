Tech watch

A SIEM is only as good as the freshness of what it depends on and what it detects. This page lists what to monitor over time so the project does not silently rot. Adding libraries (dpkt, python-evtx, OAuth) raises the supply-chain surface; this is the discipline that keeps it under control.

Supply-chain discipline

  • Pin exact versions in requirements.txt; do not float.
  • Keep an SBOM (a simple list of dependencies and versions is enough to start).
  • Scan dependencies for known CVEs on a schedule (for example pip-audit).
  • Track upstream advisories for Flask, dpkt and python-evtx.
  • Confine the risky binary parsers to local mode; this keeps them off any internet-facing server and is itself a mitigation.

Detection content to keep current

Detections age as attacker techniques shift. Watch and periodically refresh against:

  • SigmaHQ community rules, for new and updated detection logic.
  • MITRE ATT&CK, for technique coverage and renames.
  • LOLBAS and GTFOBins, for living-off-the-land binaries on Windows and Linux.
  • Public incident reports (CERT-FR, Mandiant, CrowdStrike), to prioritize tools by real-world frequency rather than theoretical risk.

Platform changes that can break ingestion

  • Windows event schema and audit policy defaults (EVTX, 4688 CommandLine inclusion).
  • auditd record formats across distributions.
  • Elastic / ECS field naming across versions.
  • PCAP link-layer and protocol coverage as captures vary.

Planned integrations to track

  • Webhook bridge to a companion app, the future integration point toward Ghidra and heavier offline analysis. Kept separate to isolate the reverse-engineering surface.
  • Mail providers (Gmail, Outlook) OAuth read-only, professional mailboxes only.

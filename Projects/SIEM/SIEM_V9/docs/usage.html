Usage documentation

One command gets you a working app. The other scripts are optional tools. Here is what each does and what works where.

The launchers (all in scripts/)

ScriptWhat it doesRun it?
start.sh / start.bat Starts the app in local mode and opens the browser. Data already in out/large shows immediately; you run new captures from the Run tab inside the app. This is the single "launch everything" entry. Yes, normally
docs.sh / docs.bat Opens this HTML documentation in your browser. When you need the docs
pipeline.sh / pipeline.bat Optional. Runs the detection pipeline on a data file from the command line, without the UI. The Run tab does the same thing. Advanced only
run_tests.sh / run_tests.bat Runs the whole test suite and prints PASS/FAIL per file and a total. To verify a build
server.sh / server.bat Placeholder. Multi-user / server mode is not implemented yet (v10). It deliberately does not start a network server, since that would be unsafe without auth. Not yet

Why start is "everything at once". The app is the product. Viewing tickets and running new analyses both happen inside it. You no longer choose between a separate "run the pipeline" step and a separate "open the UI" step; start does the whole thing and the browser opens by itself.

run local versus run siem, the old confusion

The previous scripts split two unrelated things: run_local started the web app, while run_siem was a batch processor that turned a data file into tickets. They are now start (the app, what you use) and pipeline (the optional batch tool). The duplicate and platform-specific launchers at the project root are gone; everything lives in scripts/.

Why file analysis is local only

Online, an analyst does not push a Wireshark capture or a Windows event log through a shared web app; those artifacts live on the analyst workstation, and a regular user neither has nor can produce them. Exposing a file browser and binary parsers on a server adds path-traversal and parser-exploit risk for no operational gain. So the analyze-a-file capability stays local.

In multi mode the file browser and run-on-file UI are hidden; JSON and syslog arrive through controlled server-side feeds or the streaming capture, not analyst uploads. PCAP and EVTX are local only and never exposed in multi, being the most security-sensitive.

Live capture (v9)

A special streaming mode follows a local file: new lines flow through the pipeline and tickets appear in near real time. This is not a system agent; it is a file-tail streaming ingest, available locally.

Command line, for reference

PYTHONPATH=src python3 -m ingest.replay \
  --input samples/demo_linux_attack.jsonl \
  --out-dir out/large --format auto
